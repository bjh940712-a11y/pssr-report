# 공급전 안전점검 결과보고서 웹앱 — 배포·설정 안내

| 파일 | 용도 |
|---|---|
| `index.html` | 사무실 PC용 본 앱 (ERP 불러오기 · 보고서 · 엑셀/PDF/인쇄 · 첨부 병합 · 현장 사진함) |
| `field.html` | 현장 휴대폰용 페이지 (기밀시험 결과지 촬영 · 기타 서류 스캔 · 서명 받기 → 업로드) |
| `firebase-config.js` | Firebase 연결 설정 (1회 입력) |
| `firestore.rules` | Firestore 보안 규칙 (Firebase 콘솔에 붙여넣기) |
| `firebase-messaging-sw.js` | 휴대폰 아침 알림 수신 |
| `scripts/`, `.github/workflows/` | 매일 09:00 알림·정리 프로그램 (GitHub Actions) |
| `companies.lock.js` | (선택) 시공업체 목록 갱신용 암호화 파일 — 관리자가 앱에서 만들어 올림 |

> 서버(Firestore)에는 **기밀시험 결과지 사진, 기타 서류 스캔(보일러 확인서·필증 등), 서명 그림, 미리보기·촬영번호(예: 10/23 #3)·시각**만 저장됩니다.
> 주소·이름·계약번호 같은 글자 정보 필드와 시공내역서 PDF는 저장할 수 없도록 앱과 보안 규칙 양쪽에서 막혀 있습니다.
> 예외: **현장 목록**(13단계)은 시설명·주소를 **암호화한 상태로만** 7일간 보관합니다.
> 사진은 업로드 7일 뒤 서버에서 자동 삭제됩니다 (첨부·병합해도 그 전에 지워지지 않음).

---

## 1단계. Firebase 프로젝트 만들기 (무료 Spark 요금제, 카드 등록 불필요)

1. https://console.firebase.google.com 접속 → 회사용 Google 계정으로 로그인
2. **프로젝트 추가** → 이름 예: `pssr-yeongcheon` → Google 애널리틱스 **사용 안 함** → 만들기
3. 프로젝트 개요 화면에서 **웹(</>) 아이콘** 클릭 → 앱 닉네임 예: `pssr-web` → *Firebase 호스팅은 체크하지 않음* → 앱 등록
4. 화면에 나오는 `const firebaseConfig = { ... }` 의 중괄호 안 값을 복사해 **`firebase-config.js`** 에 붙여넣기

```js
window.FIREBASE_CONFIG = {
  apiKey: "AIza....",
  authDomain: "pssr-yeongcheon.firebaseapp.com",
  projectId: "pssr-yeongcheon",
  storageBucket: "pssr-yeongcheon.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcd..."
};
```

## 2단계. Firestore 데이터베이스 만들기

1. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
2. 버전: **Standard**, 위치: **asia-northeast3 (서울)** — *위치는 나중에 바꿀 수 없습니다*
3. **프로덕션 모드에서 시작** → 만들기
4. 상단 **규칙** 탭 → 기존 내용을 모두 지우고 `firestore.rules` 파일 내용을 붙여넣기 → **게시**

## 3단계. 로그인(직원 계정) 설정

1. **빌드 → Authentication → 시작하기 → 로그인 방법** 탭 → **이메일/비밀번호** → 사용 설정 → 저장
2. **사용자** 탭 → **사용자 추가** → 직원 이메일·비밀번호 입력 (현장·사무실 같은 계정 사용 가능)
3. 추가된 사용자의 **사용자 UID** 복사
4. **Firestore Database → 데이터** 탭 → **컬렉션 시작**
   - 컬렉션 ID: `members`
   - 문서 ID: 방금 복사한 **UID**
   - 필드: `active` / 유형 boolean / 값 true → 저장
5. 직원을 추가할 때마다 2~4 반복 (members 문서가 없으면 로그인해도 사진함을 쓸 수 없습니다)
   - 퇴사·이동 시: members 문서 삭제 + Authentication에서 사용자 사용 중지

## 4단계. 서버 자동 삭제

- 무료(Spark) 요금제에서는 Firebase TTL 정책을 만들 수 없음 (403 권한 오류) → 설정하지 않음
- 대신 앱이 7일 지난 사진을 지움: 직원은 앱을 열 때 자기 사진, 마스터는 사진함을 열 때 전체
- 15단계(아침 알림)를 설정하면 매일 09:00 서버 프로그램이 7일 지난 자료를 함께 지웁니다 (아무도 앱을 열지 않아도)

## 5단계. GitHub Pages 배포

1. https://github.com 로그인 → 오른쪽 위 **+ → New repository**
   - 이름 예: `pssr-report`
   - 공개 범위: **Public** (무료 GitHub Pages는 Public 저장소만 가능)
   - 시공업체 목록은 암호화되어 있어 파일을 열어봐도 업체명·연락처를 읽을 수 없습니다 (아래 7단계 참고)
2. 저장소 화면 **Add file → Upload files** → `index.html`, `field.html`, `firebase-config.js`, `companies.lock.js`, `firestore.rules`, `README.md` 끌어다 놓기 → **Commit changes**
3. **Settings → Pages** → Source: **Deploy from a branch** → Branch: `main` / `(root)` → **Save**
4. 1~2분 뒤 표시되는 주소 확인
   - PC: `https://<GitHub아이디>.github.io/pssr-report/`
   - 현장: `https://<GitHub아이디>.github.io/pssr-report/field.html`
5. **Firebase 콘솔 → Authentication → 설정 → 승인된 도메인 → 도메인 추가** → `<GitHub아이디>.github.io`

> 수정본을 올릴 때는 같은 방법으로 파일을 다시 업로드(덮어쓰기)하면 됩니다. 각 PC의 작업 내용(수정값·첨부·업체)은 유지됩니다.

## 6단계. 사용 방법

**현장(휴대폰)**
1. `.../field.html` 접속 → 직원 계정 로그인 (한 번 로그인하면 유지)
2. 브라우저 메뉴 → **홈 화면에 추가** 하면 앱처럼 실행 가능
3. **📷 결과지 촬영** → 자동 압축·전송 → 「✓ 전송 완료」 확인

**사무실(PC, Chrome/Edge)**
1. ERP 파일 불러오기 → 건 선택
2. 상단 **📷 현장 사진함** → 처음 한 번 로그인 → 촬영번호·시각으로 사진 확인(클릭하면 크게 보기)
3. 사진을 편집 화면 **「5. 추가 첨부파일」로 끌어다 놓기** 또는 **현재 건에 첨부**
4. **📎 첨부 병합 PDF 저장** → 저장 폴더에 PDF 생성 (서버 사진은 7일 뒤 자동 삭제)

**HTML 파일만 받아 쓰는 PC**: `index.html` → 「기본값 설정」 탭 → 「현장 사진함 연결」에 firebaseConfig 붙여넣기 → 설정 저장

## 7단계. 시공업체 목록 (암호화) 관리

- **보고서 자동 채우기는 비밀번호 없이** 동작합니다. 업체 정보 하나하나가 그 업체의 ERP 업체명으로 잠겨 있어, ERP 파일에 해당 업체명이 있을 때만 그 업체 정보가 열립니다.
- **「시공업체 관리」 탭은 관리자 비밀번호**를 입력해야 목록이 보입니다. 페이지를 닫거나 「잠그기」를 누르면 다시 잠깁니다.
- 초기 관리자 비밀번호는 별도로 전달받은 값을 사용하고, **처음 한 번 꼭 바꿔 주세요.**

**비밀번호 변경 / 업체 추가·수정을 모든 직원에게 반영하는 방법**
1. 「시공업체 관리」 → 비밀번호로 열기 → 업체 추가·수정
2. **🔒 배포용 목록 만들기 / 비밀번호 변경** → 새 비밀번호 2회 입력 → `companies.lock.js` 다운로드
3. GitHub 저장소에 `companies.lock.js` 업로드(덮어쓰기) → 모든 직원에게 새 목록·새 비밀번호 적용

> 주의: 업체명을 미리 알고 하나씩 대입해 보는 방식까지 막지는 못합니다 (ERP 자료 없이 목록 전체를 보는 것을 막는 수준).
> 관리자 비밀번호는 12자 이상, 다른 곳에 쓰지 않는 값으로 정해 주세요.
> HTML 파일만 따로 받아 쓰는 PC는 `companies.lock.js`가 없으므로, 업체 목록을 바꾸면 새 `index.html`을 다시 전달해 주세요 (요청 시 재빌드).

## 8단계. 안전교육 및 개인정보 동의서 (현장 서명)

- 현장 휴대폰: 촬영 화면 위쪽 **✍️ 서명 받기** → 개인정보 동의/미동의, LPG 확인/해당없음 선택 → 사용자(필수)·시공자·LPG공급자·공급자 서명 → **서명 완료 → 확인** → **⬆ 서명 업로드**
  - 서버에는 서명 그림과 선택값만 올라가며 이름·주소는 올라가지 않습니다 (7일 뒤 자동 삭제)
- 사무실 PC: 📷 현장 사진함의 「✍ 서명」 항목 → 건 선택 → **현재 건에 적용**
  - 편집 화면 **6. 안전교육 및 개인정보 동의서**에서 상호·대표자(ERP 자동 입력)·체크 항목 확인, PC에서 직접 ✍ 서명도 가능
  - 공급자 서명은 「내 서명」으로 저장하면 다음부터 자동으로 들어갑니다
  - 「병합 PDF에 포함」이 켜져 있으면 병합 PDF의 2쪽(보고서 다음)에 들어갑니다
- **이 기능을 쓰려면 `firestore.rules`를 다시 게시해야 합니다** (서명 종류 허용 추가)

## 9단계. 첨부 PDF(시공내역서 등)에 서명 붙이기

- 편집 화면 「5. 추가 첨부파일」에서 PDF 옆 **✍** 버튼 → 페이지가 열림
- 위쪽의 서명(사용자=건물주, 시공자, LPG공급자, 공급자=내 서명)을 누르거나 페이지로 끌어다 놓기 → 위치 이동, 오른쪽 아래 모서리로 크기 조절 → **저장**
- 병합 PDF를 저장할 때 그 자리에 서명이 찍힙니다 (원본 첨부파일은 그대로)
- 서명은 「6. 안전교육 및 개인정보 동의서」에서 받거나 적용한 것을 사용합니다

## 10단계. 휴대폰 앱으로 설치 (PWA)

- GitHub에 함께 올릴 파일: `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`, `favicon.png`
- **안드로이드(Chrome/삼성 인터넷)**: 사이트 접속 → 화면의 「📲 앱 설치」 또는 메뉴(⋮) → 「앱 설치」
- **아이폰(Safari)**: 공유 버튼(□↑) → 「홈 화면에 추가」
- 설치하면 홈 화면 「공급전점검」 아이콘 → 현장 촬영·서명 화면이 주소창 없이 전체 화면으로 열림
- 아이콘을 길게 누르면 「결과지 촬영 / 서명 받기 / 보고서 화면」 바로가기 (안드로이드)
- 앱 화면은 휴대폰에 저장되어 신호가 약해도 열리며, 업로드는 인터넷 연결 시 가능

## 11단계. 계정 권한 (마스터 / 일반)

| 구분 | members 문서 필드 | 사진함에서 보이는 것 |
|---|---|---|
| 마스터 (관리자) | `active` true + **`role` = `admin`** | 모든 직원이 올린 사진·서류·서명 |
| 일반 (직원·체험) | `active` true (role 없음) | **자기가 올린 것만** |

- 새 직원은 role 없이 등록하면 자동으로 일반 계정 (실수로 전체 권한이 생기지 않음)
- 일반 계정은 현장 업로드와 PC 첨부를 **같은 계정**으로 해야 자기 사진이 보임
- 7일 지난 사진 정리: 각 직원이 촬영 화면·사진함을 열 때 **자기 사진**을, 마스터가 사진함을 열 때 **전체**를 정리 (무료 요금제에서는 Firebase TTL 자동삭제를 쓸 수 없음)

## 12단계. 기타 서류 스캔 (보일러 시공·보험가입확인서, 가스안전공사 필증 등)

> ⚠ **Firestore 규칙을 최신 `firestore.rules`로 다시 게시해야 합니다** (12·13단계 기능용). 파일 전체를 Firebase 콘솔 → Firestore Database → 규칙에 붙여넣고 「게시」. 게시 전에는 서류 업로드·현장 목록 보내기가 「권한 없음」으로 실패합니다 (결과지·서명은 그대로 됨).

1. 휴대폰 현장 화면에서 **「📄 기타 서류」** 탭 → 서류 종류(보일러 확인서 / 필증 / 기타) 선택 → **「서류 스캔 촬영」**
2. 찍으면 서류 테두리를 **자동으로 찾아** 파란 점 4개로 표시합니다. 틀리면 점을 손가락으로 끌어 모서리에 맞춥니다 (끄는 동안 확대경 표시). 「전체」는 자르지 않고 사진 전체 사용, 「회전」은 90° 회전
3. 「✓ 자르기」 → 반듯하게 펴고 **스캔 보정**(그림자 제거·배경 하얗게·글씨 진하게, 도장·서명 색은 유지)한 결과를 확인 → 필요하면 「원본 색」, 「모서리 다시」, 「회전」 → **업로드**
4. 사무실 PC 현장 사진함에 `📄 10/27 필증 #1` 처럼 표시 → 「현재 건에 첨부」하면 **「가스안전공사 필증 (현장 10/27 필증 #1).pdf」** 로 A4 PDF가 되어 첨부·병합됩니다

- 서류 사진도 결과지·서명과 같이 **업로드 7일 뒤 서버에서 자동 삭제**됩니다 (주소·이름 같은 글자 정보는 따로 저장하지 않지만, 서류 사진 자체에는 개인정보가 보일 수 있습니다).
- 잘 인식되게 찍는 법: 서류보다 **어두운 바닥** 위에 놓고, 네 모서리가 모두 화면에 들어오게.

## 13단계. 현장 목록 (점검할 건을 휴대폰에서 골라 촬영 → PC에서 자동 분류)

**흐름**
1. 출발 전: ERP에서 점검상태를 「미점검 → 적합 → 미점검」으로 바꾼 뒤, 공급전 안전점검 화면에서 **엑셀출력(화면)**
2. PC 웹앱에 그 엑셀을 불러오고 **「📤 현장 목록 보내기」** (체크한 건만, 체크가 없으면 전체)
3. 현장 휴대폰: 맨 위 **「📍 점검 중인 건 → 건 선택」**에서 지금 점검하는 곳을 고른 뒤 결과지 촬영·기타 서류·서명 → 자료에 그 건 표시가 붙어 올라감
4. 사무실 PC: 왼쪽 목록에 `📍 현장 2` 배지 → 건을 고르면 현장 사진함 맨 위에 그 건 자료가 모여 있고 **「이 건 자료 모두 첨부」** 한 번으로 결과지·서류는 PDF 첨부, 서명은 동의서에 적용

**건을 잘못 골랐을 때 (건 변경)**
- 현장 화면 「내가 올린 자료」에서 해당 자료의 **「건 변경」**(건 없이 찍은 자료는 「건 지정」) → 맞는 건 선택. 사진·서명은 그대로이고 건 표시만 바뀌며, PC에서도 바로 맞는 건으로 모임
- 바꾼 자료에는 「건 변경됨 (이전 → 새 건)」이 표시됨
- **PC에서 이미 첨부(보고됨)한 자료는 바꿀 수 없음** → PC에서 잘못 넣은 첨부를 ✕로 지우고, 맞는 건을 연 뒤 「다른 자료」 칸에서 「현재 건에 첨부/적용」
- 본인이 올린 자료만 바꿀 수 있고, 휴대폰 목록에는 오늘 올린 자료만 보임 (지난 자료는 PC에서 위 방법으로 처리)
- 다른 고객에게 서명을 받은 경우는 건을 바꾸면 안 됨 → 삭제 후 해당 고객에게 다시 서명
- ⚠ 이 기능은 **보안 규칙(firestore.rules)을 다시 게시**해야 동작합니다

**보내는 정보와 보호 방식 (자동 열쇠 방식)**
- 보내는 것: 시설명·주소(괄호 앞까지)·구분(신규 등)·검사요청일 **만**. 전화번호·입금자·금액·업체 정보는 보내지 않음
- 서버에는 AES-256 암호문만 저장 → Firebase 콘솔에서 봐도 내용을 알 수 없음. 7일 뒤 자동 삭제
- 건 번호는 계약번호를 열쇠로 변환한 16자리 값이라 서버에서 어느 계약인지 알 수 없음
- 열쇠(`teamKeys/main`)는 **마스터 계정이 처음 「현장 목록 보내기」를 할 때 자동 생성**되고, 등록 직원(members)만 읽을 수 있음. 그 전에는 일반 계정으로 보낼 수 없음
- ※ 열쇠와 암호문이 같은 서버에 있으므로 실제 보호 수준은 「등록 직원만 볼 수 있음」과 비슷합니다. 더 강하게 하려면 추후 **지사 공용 비밀번호 방식**으로 전환 (목록에 방식 표시 `m: auto`를 남겨 두어 전환 가능)

## 14단계. 일일업무현황 붙여넣기 (팀즈 공동편집 엑셀)

1. ERP 엑셀을 불러온 뒤 **「📋 일일업무현황」**
2. 검사요청일(기본: 오늘)을 고르면 「3. 공급 전 안전점검」 표 순서대로 미리보기:
   **수요처(계약명) · 위치(주소) · 시공업체 · 연락처 · 검사구분 · 세대수 · 검사자**
   - 주소는 `영천시 바깥완산길 104-3 (완산동 171번지)` 형태로 자동 정리
   - 칸을 눌러 복사 전에 고칠 수 있음 (ERP에 비어 있는 칸은 노란색)
3. 「📋 n건 복사」 → 팀즈 엑셀에서 **수요처 열의 첫 빈칸**을 클릭하고 **Ctrl+V**
   - 기본은 값만 복사 (엑셀 칸의 기존 서식 유지). 「서식 함께 복사」를 켜면 연두색 배경·테두리도 함께
   - 「일자」 열 포함을 켜면 맨 앞에 `10/27(화)` 열이 붙음
- 이 기능은 서버를 쓰지 않습니다 (PC 브라우저 안에서만 처리).

## 15단계. 아침 9시 「보고하셨나요?」 알림 (휴대폰 푸시)

매일 09:00(한국시간) GitHub Actions가 서버를 확인해, **보고(PC 첨부) 전인데 내일까지 지워질 자료**가 있으면 알림을 보냅니다.
- 자료를 올린 직원: 「현장 자료 2건(결과지 1·서류 1)이 내일(11/6 금) 15:20에 서버에서 삭제됩니다…」
- 마스터 계정: 「미보고 5건 (직원 3명) · 그중 4건이 오늘 13:00부터 삭제」 전체 요약
- PC에서 「현재 건에 첨부/적용」한 자료는 **보고됨**으로 표시되어 알림에서 빠집니다.
- 알림 문구에는 건수와 날짜만 들어가고 이름·주소는 들어가지 않습니다.
- 같은 프로그램이 7일 지난 자료도 서버에서 지웁니다.

**처음 한 번 설정 (관리자)**
1. **웹 푸시 키:** Firebase 콘솔 → ⚙ 프로젝트 설정 → **클라우드 메시징** 탭 → 아래 「웹 구성 → 웹 푸시 인증서」 → **키 쌍 생성** → 나온 긴 키를 복사해 `firebase-config.js` 마지막 줄 `window.FIREBASE_VAPID_KEY = "여기";` 따옴표 안에 붙여넣기
2. **서비스 계정 키:** 같은 프로젝트 설정 → **서비스 계정** 탭 → 「새 비공개 키 생성」 → JSON 파일이 내려받아짐 (⚠ 이 파일은 관리자 열쇠입니다. GitHub에 파일로 올리지 마세요)
3. **GitHub 비밀값:** 저장소 → Settings → Secrets and variables → **Actions** → New repository secret → 이름 `FIREBASE_SERVICE_ACCOUNT`, 값에 2번 JSON 파일 내용 전체 붙여넣기 → 저장 (그 뒤 JSON 파일은 PC에서 지워도 됨)
4. **파일 올리기:** `firebase-messaging-sw.js`, `scripts/remind.mjs`, `scripts/remind-plan.mjs`, `.github/workflows/pssr-reminder.yml` (폴더 구조 그대로)
5. **시험:** 저장소 → **Actions** 탭 → 「현장 자료 보고 알림」 → Run workflow (dry_run `1` = 보내지 않고 확인만) → 기록에 계획된 알림이 보이면 성공

**직원 휴대폰**
- 현장 화면 위 **「🔔 알림 받기」** → 허용. 안드로이드는 Chrome이나 설치한 앱에서, **아이폰은 홈 화면에 설치한 앱에서만**(iOS 16.4 이상) 됩니다.
- 알림을 누르면 현장 화면이 열립니다.

> 참고: GitHub 예약 실행은 몇 분~수십 분 늦을 수 있고, 저장소에 60일 동안 아무 변경이 없으면 GitHub이 예약 실행을 멈춥니다 (Actions 탭에서 다시 켜면 됨).

## 보안 메모

- `firebase-config.js`의 apiKey는 공개되어도 되는 값입니다 (Firebase 공식 안내). 데이터 접근은 **로그인 + members 등록 + 보안 규칙**으로만 허용됩니다.
- 누군가 apiKey로 임의 계정을 만들어도 `members`에 없으면 아무것도 읽거나 쓸 수 없습니다.
- 결과지·기타 서류 종이에 고객명·주소가 인쇄되어 있다면, 사진이 서버에 머무는 동안(최대 7일)에는 해당 정보가 포함됩니다. 필요 시 촬영 범위를 사내 기준에 맞게 정해 주세요.
